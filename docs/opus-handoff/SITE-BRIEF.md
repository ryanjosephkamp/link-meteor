# GitHub Pages site brief

Design and build an original public site for Link Meteor in this same project/repository. The site has not been implemented or deployed. Inspect the project and create your own scaffolding; select the visual direction, technology, structure, and development approach using your judgment. This is a separate deliverable from extension refinement.

The audience is researchers collecting sources and people handling link-heavy admin panels, ticket systems, and product listings. The central promise is: select links, retain their actual labels and origins, organize them locally, and export useful results. Link Meteor is completely free forever. There is no account, telemetry, advertising, paid tier, or hosted service requirement.

Useful outcomes include an engaging explanation of regional capture; clear examples of separate anchor-text and URL exports; honest descriptions of multi-tab capture and local collections; accessible installation/help/privacy pages; and a safe practice/demo page with realistic links. Use original branding, assets, writing, and implemented screenshots or clearly labeled illustrations. The reference product provides functional context only.

Explain the installation path appropriate to the current state. The extension has not been submitted to the Chrome Web Store: do not fabricate a store listing, review score, user count, endorsement, or install URL. A development-build path can be clearly labeled until the user approves a real store release. Keep permission and coverage limitations accurate, including browser bookmark-sync behavior. Do not suggest Firefox/Safari support exists.

Design for narrow and wide screens, keyboard use, reduced motion, clear contrast, and a quick, readable experience. No analytics or remote collection of user links. A demo should use synthetic/public sample data and should not imply that arbitrary webpage contents are sent to a service.

Prepare the site for eventual GitHub Pages hosting and explain any remaining deployment steps, but do not deploy, change account/repository security settings, or publish the extension. Return actual screenshots, checks, source identity, outstanding work, and any assumptions. The user will review and bring the combined result back to Astra for a final extension functionality audit.
