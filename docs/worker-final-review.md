# Final bounded source review — 2026-09-25

Read-only pass over the current `src/` snapshot. Scope was material data loss, false success, permission boundaries, and malformed exports. No source, test, Git, or browser changes were made. The driver reported passing focused and browser suites; the edge paths below were not claimed by those results.

## Findings

1. **P1 — One admitted `mailto:` candidate can fail a whole tab capture.** The capture script accepts any URL whose parsed protocol is `mailto:` (`src/content/capture.js:22-23`), and background occurrence conversion uses the same scheme-only check (`src/background.js:102-108`). The reducer then rejects `mailto:?subject=Hello` because `URL.pathname` is empty (`src/core/model.js:36-43`); `captureTabs` catches the append failure and reports the tab as an error with zero links (`src/background.js:132-140`). Other valid links on that tab are not persisted. Text and Markdown export also reject this admitted URL (`src/core/export.js:43-49`). A read-only Node reproduction confirmed `new URL('mailto:?subject=Hello').protocol === 'mailto:'`, followed by the reducer and text-export errors. Align candidate, model, and export validation; a single unsupported candidate should be skipped with explicit coverage reporting rather than discard all valid links in that capture.

2. **P2 — A chosen tab that closes during the permission prompt disappears from the UI report.** `runCapture` takes the initial selected scope (`src/ui/workbench.js:367-376`), refreshes inventory after the prompt, and sends only IDs remaining in `freshTabs` (`src/ui/workbench.js:380-385`). If a selected tab closes in that interval, it is omitted from `tabIds`, so background never executes its closed-tab error path (`src/background.js:119-140`). Keep the originally chosen IDs for the batch, while separately checking whether surviving tabs changed origin. The driver's closed-tab browser check calls `capture.run` with an invalid ID directly; it does not exercise this UI handoff race. This is a code-path finding, not a reproduced browser interaction.

3. **P2 — A saved region can be reported as failed and saved again if Review cannot open.** `commitCapture` persists the links before awaiting `chrome.tabs.create` for Review (`src/background.js:148-154`). If tab creation fails, the message rejects despite the successful save. The overlay sets `committed=true` only after the response (`src/content/capture.js:171-175`), so a retry of Add or Review appends the same selected links as new occurrences. Return a successful save plus a separate Review-open warning, or make a retry idempotent. This is a definite error-path sequence; tab-creation failure was not induced in a browser.

No new confirmed permission-boundary defect or malformed XLSX structure was found in this pass. General regional capture, export, hold, and restart evidence supplied by the driver does not establish the three edge paths above.

## P1 core repair handback

The core validation/export mismatch in finding 1 is repaired in `src/core/model.js` and `src/core/export.js`: `mailto:?subject=Hello` and `mailto:` are accepted as recipientless mail links, while an empty `tel:` destination, whitespace/control characters, `javascript:`, and `data:` remain rejected. Text export returns each valid URL string exactly; Markdown escapes only its link delimiters. The mixed append test includes ordinary web, addressed email, both recipientless forms, and telephone occurrences in one action and checks that all survive. Export tests cover both recipientless forms and the rejected cases.

Checks actually run: the pre-change focused suite passed 12/12. After adding the new regression cases but before the repair, 10/12 passed, with the mixed append and text/Markdown tests failing on recipientless mail URLs as expected. After the repair, `node --test tests/core.test.mjs tests/export.test.mjs` passed 12/12 with zero failures. No browser or Git action was performed by this worker.
